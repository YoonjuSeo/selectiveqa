## 0. 작성 시점과 공개 사항

- **이미 확인한 결과:** EXAONE Tier 1의 Q1~Q5 결과(G 창별 값 포함)는 이 부록을 쓰기 전에 확인했다. 따라서 5절의 판정 경계 수치는 EXAONE 값을 알고 정한 것이다. 규칙의 구조(방향 조건과 2 SD 기준)는 원문 4.4절을 그대로 옮기고, 바뀐 것은 변동 단위(seed → 20-step 창)뿐이다. 창 범위와 방향 조건은 원문 문언에 가장 가까운 쪽(모든 창 포함, 모든 창 같은 방향)으로 정했다.
- **아직 확인하지 않은 결과:** Qwen3 Tier 1은 이 부록을 커밋하기 전까지 학습을 시작하지 않는다.
- **범위 결정:** GPU 예산 때문에 seed 42만 실행한다(원문 2.1절의 "43·44 권장"은 미실행). 원문 4.4절에 따라 Q2~Q5는 모두 **탐색적**이며 "차등 있음" 대신 "차등 시사"로 표기한다. Q2를 확증적으로 판정하려면 두 모델 모두 3 seed가 필요하고, 이는 향후 과제로 남긴다.
- **seed 추가 금지:** seed 42 결과를 본 뒤 결과에 따라 seed를 추가하지 않는다. 나중에 seed를 추가하게 되면 새 부록을 먼저 커밋하고, 결과와 무관하게 결정했다는 근거를 적는다.

## 2. Qwen3 실행 계획

### 2.1 학습

설정은 원문 2.1절과 같다. `config_qwen3.yaml`을 쓰며, 이 설정 파일이 `enable_thinking=False`로 비사고 모드를 고정한다.

```
modal run --detach modal_train_diag.py --model qwen3 --train-file train.jsonl \
    --tag _m1_diag --seed 42 --ckpt-interval 20
modal run --detach modal_train_diag.py --model qwen3 --train-file train_mix_r05.jsonl \
    --tag _r05_diag --seed 42 --ckpt-interval 20
```

- 코드는 3절의 로깅 변경만 반영한 버전을 쓰고, 두 실행 모두 같은 커밋에서 돌린다.
- 학습 전후 스키마 자동 검증(`SCHEMA_VERSION`)을 통과해야 한다.
- 저장할 때마다 NaN/Inf 점검을 한다. seed 42는 원 실험에서 최종 체크포인트가 발산했던 이력이 있다. 발산이 감지되면 그 사실과 시점을 기록하고, 해당 실행의 분석 가능 여부는 4.1절 결측 규칙으로 판단한다.

### 2.2 평가

- **Q1 재현 확인:** eval_full_v2 전체, 제외 30건, greedy, `max_new_tokens` 128. ΔEM과 R_tok은 같은 seed의 **원 Qwen3 M1**(`preds_M1` s42) 대비로 계산한다(원문 4.2절).
- **Q5 체크포인트 평가:** Answerable 200문항(λ 스윕, EXAONE Q5와 같은 부분집합). 코사인 기준은 **원 Qwen3 M1 s42 어댑터**(`qwen3/qlora_adapter_s42`, 무결성 확인 완료)이고, 계산 방법은 Tier 0 b와 같다.
- **5절 2단계(학습 재현 확인):** 재학습 aggregate loss 곡선을 원 Qwen3 학습 로그와 겹쳐 그린다.

### 2.3 EXAONE 쪽 정리 (Qwen3 결과 확인 전에 수행)

- **Q1 "제외 34건" 해소 (완료, 2026-09-26 재실행으로 확인):** `evaluate_followup.py --m2-glob "preds_M2_r05_diag_s*.jsonl" --tag r05_diag_recheck`(기본 인자, 즉 `excluded_gold_v2.json` + `excluded_gold_v2_manual.json`)로 재실행한 결과, 콘솔은 "누적 25건" → "누적 34건"을 출력했다. 원인은 `load_exclusions()`가 `data.values()`로 dict의 모든 값을 순회하면서, `question_ids` 목록 외에 `rule`·`date`·`judged_by` 같은 메타데이터 **문자열**까지 `isinstance(it, str)` 조건에 걸려 제외 ID로 잘못 추가하는 버그다(파일1: 실제 ID 24 + rule 문장 1 = 25건 표시, 파일2 추가분: 실제 ID 6 + rule·date·judged_by 문장 3 = 9건 표시, 누적 34건). 이 가짜 "ID"는 실제 문항 ID와 겹치지 않으므로 `build_rows()`의 집합 차집합 연산에는 영향을 주지 않는다. 실제로 재실행 결과 **n=1737**(=1767−30, 진짜 제외 30건과 정확히 일치)이고, ΔEM −0.349 [−0.378, −0.321]·H1~H5 판정이 기존 보고값과 완전히 동일했다. **결론: 기존 Q1 결과는 처음부터 30건 기준으로 정확히 계산되어 있었고, "34건" 표기는 콘솔 로그 집계 버그(id가 아닌 메타데이터 문자열까지 카운트)였을 뿐 실제 필터링이나 지표에는 영향이 없다. 재산출은 불필요.** 다만 `load_exclusions()`를 `data.get("question_ids", [])`만 읽도록 고쳐 두면 향후 같은 혼동을 막을 수 있다(권장, 필수 아님).

## 3. 콜백 검증 방식 변경 (원문 5절 1단계 대체)

EXAONE에서 원문 5절 검증식이 44개 step 전부에서 불일치했다(9절 이탈 기록 참조). 원인은 두 값의 통계량 정의가 다르다는 데 있다. `loss_total`은 예제별 비율의 평균(mean of ratios)이고, 검증식은 토큰 가중 전역 평균(ratio of sums)이다. 이 구조는 Qwen3에서도 같으므로, 검증식을 그대로 쓰면 같은 불일치가 반복된다. Qwen3 실행부터 다음과 같이 바꾼다.

**확인된 사실 (코드 검토, `src/training/train_qlora_diag.py` `UASplitTrainer.compute_loss`):**
- `config_qwen3.yaml`도 EXAONE과 같이 `batch_size=1, grad_accum=16`이다. 즉 micro-batch 하나 = 예제 1건이다.
- `compute_loss`는 `loss = per_example_loss.mean()`을 반환하며, 예제가 1건뿐이므로 이 값은 **그 예제 하나의 토큰 정규화 loss**(`s_loss_i / n_tok_i`) 그 자체다.
- `compute_loss`는 `num_items_in_batch` 인자를 받기만 하고 쓰지 않으므로, transformers의 토큰-가중 loss 평균 기능은 적용되지 않는다.
- `logging_steps=1`(optimizer step마다 로그)이므로, HF Trainer가 보고하는 `loss_total`은 **그 step에 들어간 16개 예제의 micro_loss를 단순 산술평균한 값**이다: `loss_total(step) ≈ (1/16) Σ_{i=1..16} micro_loss_i`. 이는 이탈 기록(9절 원문)에서 진단한 "mean-of-per-example-ratios"와 정확히 일치한다.

**로깅 추가 (읽기 전용, gradient 경로 불변, 원문 2.2절 범위 안):**
- 매 optimizer step 안의 각 micro-batch(=예제)마다 `compute_loss`가 반환하는 `loss.item()`을 `micro_loss` 리스트로 기록한다(batch=1이므로 예제별 값과 같다. 예제별 합/토큰 수를 따로 또 기록할 필요는 없다).
- `SCHEMA_VERSION`을 올린다.

**검증 (분석 전 필수, 두 가지 모두 통과해야 한다):**
1. **그룹 집계 일관성:** `micro_loss`를 UA/Answerable로 나눠 `s_loss_i`(=`micro_loss_i × n_tok_i`)로 역산해 다시 합산한 값이 `sum_loss_ua`, `sum_loss_ans`, `tok_ua`, `tok_ans`와 상대오차 1e-4 이내로 일치한다.
2. **학습 loss 대조:** 해당 step의 `micro_loss` 16개 값의 산술평균이 같은 step의 `loss_total`과 1e-4 이내로 일치한다.

불일치하면 원문 5절대로 분석을 중단하고 이탈 기록에 남긴다. EXAONE 로그에는 이 필드가 없으므로, EXAONE의 기존 이탈 판단(9절 1행)은 그대로 유지한다.

**사전 점검:** 전체 학습 전에 짧은 dry run(20 step 이하)으로 위 검증이 통과하는지 확인한다. dry run 로그는 분석에 쓰지 않고, 확인 후 폐기했다고 기록한다.

## 4. G 정의 확정

### 4.1 기준선과 창

- **M1 기준선:** L_Ans^M1(w)는 **M1 진단 재학습 로그**의 토큰 가중 값(Σ`sum_loss_ans` ÷ Σ`tok_ans`)을 쓴다. 원문 4.2절은 "기존 M1 학습 로그"를 지정했으나, 그 로그의 aggregate loss는 mean-of-ratios여서 M2 쪽 토큰 가중 값과 통계량이 다르다. 원문 8절의 "M1 재학습: G 기준선 정밀화"를 근거로 바꾸고, 9절에 기록한다. EXAONE과 Qwen3에 같게 적용한다.
- **창:** 20-step 창(끝 step 기준 20, 40, …, 360, 376)을 쓴다. 2 epoch 구간은 EXAONE 보고와 같은 **10개 창(200, 220, …, 360, 376)**이다.
- **결측:** 창 안에 해당 토큰이 없으면 결측으로 둔다(원문 4.1절). 10개 창 중 하나라도 결측이면 5절 판정은 S2d(미결정)로 한다.

### 4.2 주 지표와 민감도 지표

- **주 지표:** 절대 G(w) = L_Ans^M2(w) − L_Ans^M1(w), 그리고 10개 창의 평균 Ḡ.
- **민감도 분석(보고만 하고 판정에는 쓰지 않는다):**
  - 상대 G(w) = G(w) ÷ L_Ans^M1(w)
  - step 320 창을 뺀 9개 창 평균
  - 창을 먼저 합산한 뒤 계산한 G

## 5. Q2 판정 규칙 (원문 4.4절의 seed=1 대체)

### 5.1 정의

- d(w) = G_EXAONE(w) − G_Qwen3(w), 10개 창
- D = Ḡ_EXAONE − Ḡ_Qwen3
- s = max(SD_EXAONE, SD_Qwen3). 여기서 SD는 각 모델의 10개 창 G(w)의 표본표준편차(n−1)이며, **모든 창을 포함**한다.

### 5.2 판정 (위에서부터 순서대로 적용)

| 순서 | 조건 | 판정 |
|---|---|---|
| 0 | Qwen3 재학습이 붕괴(ΔEM ≤ −0.20, 원문 6.1절) | Q2 판정 중단. "무손실형" 분류를 재검토한다. |
| 0′ | 4.1절 결측 발생, 또는 3절 검증 실패 | S2d |
| 1 | **10개 창 모두** d(w) > 0 **그리고** D ≥ 2s | **S2a** (EXAONE 쪽 차등 시사) |
| 2 | **10개 창 모두** d(w) < 0 **그리고** −D ≥ 2s | **S2c** (Qwen3 쪽 차등 시사) |
| 3 | 두 모델의 창별 G 범위 [min, max]가 겹치고 **그리고** \|D\| ≤ s | **S2b** (차등 없음 시사) |
| 4 | 그 외 | **S2d** |

### 5.3 판정 경계 미리보기 (EXAONE 값 기준, 커밋 시점 공개용)

EXAONE: Ḡ = 0.0314, SD = 0.0212 (10개 창, step 320 창 −0.0225 포함). SD_Qwen3 ≤ 0.0212라고 가정하면 s = 0.0212이다.

| 판정 | 필요 조건 (Qwen3) |
|---|---|
| S2a | Ḡ_Qwen3 ≤ −0.0110 이고 **모든 창**에서 G_Qwen3(w) < G_EXAONE(w). 특히 step 320 창에서 G_Qwen3 < −0.0225 |
| S2b | Ḡ_Qwen3가 0.0102~0.0526 범위에 있고, 창별 범위가 EXAONE 범위 [−0.0225, 0.0536]와 겹침 |
| S2c | Ḡ_Qwen3 ≥ 0.0738 이고 모든 창에서 G_Qwen3(w) > G_EXAONE(w) |

SD_Qwen3가 0.0212보다 크면 s가 커지고, 이에 따라 S2a·S2c 경계는 멀어지며 S2b 범위는 넓어진다.

**공개:** 이 규칙에서 S2a는 Qwen3의 G가 음수일 때만, 즉 UA 혼입이 Answerable 학습을 오히려 쉽게 만들 때만 가능하다. 연구자는 이를 알고 규칙을 확정했으며, 결과를 본 뒤 창 범위나 방향 조건을 바꾸지 않는다.

**한계:** 20-step 창은 seed가 아니다. 창별 변동에는 학습 추세와 자기상관이 섞여 있어 seed 간 변동을 대신하지 못한다. 이 판정은 원문 4.4절의 확증적 판정과 같은 격이 아니며, 본문에서 "창 변동 기준 탐색적 판정"으로 표기한다.

## 6. Q3~Q5 비교 (탐색적, 원문 6.3절 적용)

| 질문 | 지표 | 비교 방식 |
|---|---|---|
| Q3 (S3) | t_UA, L_UA_early | 원문 정의 그대로 두 모델 값을 나란히 제시한다. EXAONE의 t_UA가 더 늦거나 L_UA_early가 더 높으면 S3 성립으로 기술한다. 반대 방향이면 원문 6.3절의 대안 해석을 기록한다. Qwen3의 L_UA가 끝까지 0.1 아래로 안정되지 않으면 t_UA를 "미도달"로 적는다. |
| Q4 (S4) | ρ_content | 창별 분모 \|ΔL_content + ΔL_field\| < 0.005인 창은 결측으로 처리한다. 결측 창이 10개 중 5개 이상이면 그 모델의 ρ_content는 "손상 없음으로 산출 부적합"으로 보고한다. 무손실형은 분모가 0에 가까워 비율이 불안정할 수 있기 때문이다. 두 계산 방식(창별 평균, 창 합산)을 모두 보고한다. |
| Q5 (S5, S5′) | t_fmt, 체크포인트별 EM·응답 토큰·코사인 | Qwen3가 ×1.5 문턱을 넘지 않으면 t_fmt는 "미도달"로 적는다. 코사인 궤적은 Qwen3 노이즈 기준선(0.161~0.163)을 기준선으로 함께 그린다. |

**보조 기술 통계 (판정에는 쓰지 않는다):**
- 1 epoch 구간(끝 step 20~180, 9개 창)의 G(w)와 평균을 두 모델 모두 보고한다.
- 목적은 Q5에서 EXAONE 재배치가 step 20 이전에 끝난 것으로 관찰된 상황에서, 경쟁 격차가 학습 초반에 어땠는지 기술하는 것이다.

## 7. 해석 제약 (원문 6.4절 보완)

1. **S2a가 나와도 원문 6.4절 첫 행의 문장은 그대로 쓰지 않는다.** 그 문장("경쟁으로 시작되어 … 재배치하고")은 시간 순서를 전제한다. 그러나 EXAONE Q5에서 방향 전환은 step 20 이하에 이미 끝났고, G는 step 189~376 구간에서 측정한다. S2a일 때 쓸 수 있는 문장은 다음까지다.
   > "붕괴형에서는 가중치 재배치 이후에도 UA 목표와 답변 목표의 경쟁이 학습 내내 지속되며, 이 경쟁은 무손실형보다 크다(탐색적)."
2. **Q2 결과는 모두 탐색적으로 표기한다.** "확증"이나 "입증" 같은 표현을 쓰지 않는다.
3. **두 모델 비교에서 모델 간 차이를 원인으로 해석하지 않는다.** 원문 1절의 "주장하지 않을 것"이 그대로 적용된다. 모델 하나 대 하나의 비교이므로, Qwen3와 EXAONE의 다른 모든 차이(M0 UA NLL이 약 2만 배 차이, 아키텍처, 토크나이저의 BOS 정의)가 결과에 섞여 있다.

**경계 토큰 관찰(두 모델 공통, 조치 불필요):** `%",`, `["}]`처럼 값의 마지막 글자와 닫는 따옴표·쉼표·중괄호가 BPE 토크나이저에 의해 한 토큰으로 합쳐진 경우, 그 토큰 전체가 content로 분류된다(EXAONE A.1에서도 `",` 토큰이 동일하게 content로 표시됨). 이는 문자 오프셋을 토큰 단위로 매핑하는 방법(사전등록 3절)의 정밀도 한계이며, 두 모델에 동일하게 적용되므로 ρ_content 비교에 영향을 주지 않는다.

**확인 범위의 한계:** 이 출력은 **타깃(레이블) 구간만** 보여준다. 비사고 모드에서 우려했던 빈 `<think>` 블록은 통상 프롬프트(어시스턴트 턴 시작부)에 삽입되는데, 프롬프트 토큰은 loss 계산에서 마스킹되므로(원문 2.3절, 3.5절) G·ρ_content 산출에는 영향이 없다. 확인이 더 필요하면 프롬프트 원문을 별도로 출력해 눈으로 확인한다(선택).
