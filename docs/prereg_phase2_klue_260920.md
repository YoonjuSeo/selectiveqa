# Phase 2 (Stage F) 사전등록 — KLUE-MRC 도메인 축 분리

작성일 2026-09-20 · **어떤 KLUE 추론·학습 결과도 확인하기 전에 커밋**

## 1. 목적

질문은 하나다 — **EXAONE의 붕괴가 금융 도메인을 떠나도 재현되는가.**

보고서 4.2·5장에서 붕괴의 원인 후보는 다음까지 좁혀졌다. 한국어 특화 여부(Kanana가
반례), 아키텍처(Llama–Kanana 쌍이 반례), M0 답변 길이(3.0절), SFT 설정 — 혼입량
1~30%와 무응답 타깃 표면 형식(4.7절 ablation) 모두 배제됐다. 남은 후보는 ① EXAONE
개별 모델 특성(사전학습 구성·정렬 방식)과 ② 금융 도메인과의 상호작용이다. 본 실험은
도메인만 바꿔 이 둘을 가른다.

대조군으로 Kanana를 함께 돌린다. Kanana는 금융에서 무손실형으로 확정됐으므로,
"KLUE가 그냥 모든 모델을 망가뜨렸다"는 대안 설명을 배제하는 역할을 한다.

## 2. 붕괴 판별의 비교 기준 — 실행 전 고정

**문제.** 금융 붕괴 기준 ΔEM = −0.346은 4개 답 유형의 집계값이고, 유형별 기여는
numeric −14 / text −30 / table −28 / yes_no −61 %p로 yes/no가 가장 크다(보고서 표 10).
KLUE-MRC는 추출형 span 단일 유형이므로 이 집계값과 직접 비교하면 "붕괴가 사라졌다"와
"yes/no가 없어서 작아 보인다"를 구분할 수 없다.

**해법.** 비교 기준을 금융 결과의 **text_span 하위집합**으로 재정의한다. 기존 예측
파일에서 재산출했으며(추론·학습 없음), 산출 코드는 `src/analysis/comparator_textspan.py`,
값은 `results/comparator_textspan.json`에 고정했다.

| 금융, text_span 한정 (n=300, 3 seed) | ΔEM (M2-r05 − M1) | 응답 토큰 배율 | False abstention |
| --- | --- | --- | --- |
| **EXAONE (붕괴형)** | **−0.303** (SD 0.037) | **×2.33** | 3.0% |
| Qwen3 (무손실형) | +0.002 (SD 0.008) | ×0.99 | 0.0% |
| Llama (무손실형) | −0.006 (SD 0.005) | ×0.99 | 0.0% |

두 유형은 text_span만으로도 겹침 없이 갈린다. 즉 **붕괴는 yes/no 아티팩트가 아니며,
KLUE에서 측정 가능한 형태로 살아남는다.** 이것이 본 실험 설계가 성립하는 근거다.

동일성 검증: `--types all`로 돌리면 공식 판정 `metrics_followup_r05.json`의 d_em과
점추정이 1e-12 이내로 일치한다(부록 A의 제외 목록 정정이 판정을 바꾸지 않는다는 기록도
함께 확인됨). CI는 bootstrap 층 구성 차이(대상 유형 층만 재표집)로 4째 자리에서
갈리며, 이는 의도된 설계다.

**부수 발견 — false abstention은 약한 지표다.** 전체 4유형에서 8.2%였던 EXAONE의 false
abstention이 text_span 한정에서는 3.0%로 줄어든다. 판별의 실질은 ΔEM과 토큰 배율이
끌고 가며, 판정 시 이 가중을 명시한다.

## 3. 판별 규칙 — 실행 전 고정

KLUE에서 EXAONE을 다음 규칙으로 분류한다. 문턱은 §2의 두 관측 띠 바깥에 잡았다.

| 판정 | 조건 (3 seed) |
| --- | --- |
| **붕괴형 재현** | ΔEM 95% CI 상한 < −0.10 **그리고** 토큰 배율 ≥ 1.5 — 둘 다 ≥ 2/3 seed |
| **무손실형** | H2 채택(ΔEM CI 하한 > −0.03) 3/3 **그리고** 토큰 배율 ∈ [0.90, 1.15] 3/3 |
| **미결** | 위 둘 중 어느 쪽도 아님 — 그대로 보고하고 범주를 강제하지 않는다 |

## 4. 데이터 — 실사 결과와 설계 결정

실사는 `src/data_prep/audit_klue.py`, 결과는 `results/klue_audit.json`. 모델은 돌리지
않았으므로 결과에 따른 선택적 배제 위험이 없다. 구축은 `src/data_prep/prepare_klue.py`,
무결성 기록은 `data/processed/klue_manifest.json`.

| 결정 | 내용과 근거 |
| --- | --- |
| **D1 한국경제 출처 제외** | KLUE-MRC 원천은 위키피디아·한국경제·ACROFAN이며 한국경제가 train 56.4%·dev 55.8%를 차지한다. 한국경제는 경제·금융 저널리즘이므로 남기면 "금융을 떠난다"는 전제 자체가 무너진다. 제외 후에도 필요한 정원이 모두 확보된다. |
| **D2 title 단위 재분할** | KLUE 자체 train·dev가 title 2,620개를 공유한다. 금융의 문서 단위 분리 원칙을 지키려면 합쳐서 재분할해야 한다. 구축 후 누출 0 확인. |
| **D3 답 유형 = text_span 단일** | KLUE-MRC는 추출형 span만 있다. 따라서 비교 기준도 §2의 text_span 한정값을 쓴다. |
| **D4 학습 무응답은 교차 지문으로 생성** | 금융도 학습 무응답은 교차 지문(easy)만 썼고, 그 덕에 hard UA 복원이 "훈련 분포 밖 일반화"로 해석된다. KLUE의 사람이 쓴 `is_impossible`을 학습에 넣으면 처치 자체가 달라져 도메인만 바꾼 대조가 아니게 되고 hard UA의 OOD 성질도 사라진다. |
| **D5 hard UA = KLUE 네이티브 is_impossible** | 금융의 근거제거·대상치환과는 다른 종류의 hard이므로 **복원 깊이를 도메인 간에 직접 비교하지 않는다.** 1차 종점(붕괴 여부)은 응답가능 문항에서만 측정되므로 이 비대칭은 주 판정에 영향을 주지 않는다. |
| **D6 응답가능 평가 1,200건** | n=300으로 줄이면 ΔEM의 95% CI 반폭이 0.023~0.027로 넓어져 H2 문턱(−0.03)에 걸린다. 실제로 무손실 모델을 금융 text_span(n=300)만으로 판정하면 Qwen3 2/3·Llama 1/3로 떨어지는 반면 n=1,170에서는 둘 다 3/3이다. 검정력을 금융과 맞추기 위한 정원이다. |
| **D7 복수 정답 max-over-golds** | KLUE 응답가능의 35.5%가 서로 다른 정답을 2개 이상(최대 11개) 갖는다. 단일 gold로 채점하면 EM을 구조적으로 과소추정한다. |

**구성 (금융 평가셋과 동형, 총 1,767건으로 일치).**

| 구분 | 건수 |
| --- | --- |
| 학습 Answerable | 3,000 |
| 학습 혼입 r05 | 3,000 중 150건을 교차 지문 UA로 교체 (총량·질문집합·행순서 불변) |
| 평가 Answerable | 1,200 (복수 정답 422건) |
| 평가 easy UA | 300 (교차 지문, `unans_*`) |
| 평가 hard UA | 267 (KLUE 네이티브, `*-hd-na`) |

question_id 규약을 금융과 동일하게 맞췄으므로 `ua_kind()`가 easy/hard를 그대로 읽는다.
평가셋 출처 구성은 위키피디아 1,269 · ACROFAN 498이며, KLUE question_type은
1(단문 추론) 996 · 2(다문장 추론) 504 · 3(무응답) 267이다. 문서 누출 0을 확인했다.

**지문 길이.** KLUE 지문은 금융보다 길다(평가셋 중앙 865자 vs 금융 598자, p90 1,551 vs
1,206, 최대 2,034 vs 2,197). `max_seq_len: 2048`은 유지하되, 학습 실행 전 실제
토크나이저로 (시스템프롬프트 + 지문 + 질문 + 타깃) 길이를 표본 검사하고 절단이
발생하면 그 사실과 건수를 보고한다. 평가셋 정답 길이는 최대 46자로 금융의 문장형 gold
제외 규칙(100자 초과)에 걸리는 문항이 0건이다 — 금융에서 30건을 제외했던 사유가 KLUE
에서는 발생하지 않으므로 유효 표본은 1,767건 전건이다.

## 6. 판정 기준 — 변경 없음

H1·H2·H3·H5는 사전등록(260817)과 부칙(260828)을 그대로 적용한다. 지표 정의, 층화
paired bootstrap 10,000회, 판정 문턱, H4 주 신호(`m1_conf`) 모두 변경하지 않는다.
H4는 기존과 같이 탐색적으로만 보고한다.

- **H1** easy·hard 각각 M2 환각률 95% CI 상한 < M1 CI 하한, 3/3 seed
- **H2** 응답가능 전체 EM 차이(M2−M1) 95% CI 하한 > −0.03, 3/3 seed
- **H3** M1의 hard UA 환각 vs 응답가능 정답 분리 AUROC CI 하한 > 0.85, 3/3 seed
- **H5** M2의 전 유형 ΔECE(대 M0) 95% CI 상한 < 0, 3/3 seed

유형이 하나이므로 H5의 "전 유형"은 text_span 단일 항목이 된다. 이는 기준 완화가 아니라
데이터 구조에서 따라오는 결과이며, 금융과의 비교 시 명시한다.

## 7. 실행 관문 (gate)

**관문 1 — 소거의 기저.** M0에서 easy UA 무응답률이 90% 미만이면 해당 모델의 Stage F를
중단하고 그 사실만 보고한다. Stage E와 동일한 기준·동일한 논리(소거를 관찰할 기저가
없으면 설계가 성립하지 않으며, 사후 판단은 결과에 따른 선택적 배제가 된다).

**관문 2 — 바닥 효과 (Phase 2 신규).** EXAONE M1의 응답가능 EM이 3 seed 평균 **0.55
미만**이면, ΔEM 기반 붕괴 폭 비교를 **inconclusive로 보고한다.** 금융 text_span에서
M1 EM은 0.73이었고 붕괴 후 M2는 0.43이었다. M1이 이미 0.45 부근이면 같은 크기의 붕괴가
구조적으로 관측 불가능하다. KLUE는 장문 뉴스·위키 지문에 다문장 추론이 섞여 금융보다
어려우므로 이 관문을 미리 명시한다.

단, **토큰 배율과 false abstention은 EM 바닥에 영향받지 않는 비율·비중 지표이므로 관문
2에 걸리더라도 계속 보고하고 §3의 판별에 사용한다.** 관문 2는 ΔEM 항목만 무력화한다.

두 관문 모두 결과는 통과 여부와 무관하게 보고한다.

## 8. 실행하지 않는 것

- **혼입률 격자(r01·r10·r30).** 4.7절 ablation에서 1%와 30%가 구별되지 않는 크기의
  붕괴를 냈다 — 붕괴는 다이얼이 아니라 스위치다. r05 단일 지점으로 충분하다.
- **에폭별 분석, risk-coverage 곡선, 검색 불일치형 UA.** 핵심 판정이 끝난 뒤 여유가
  있으면 수행하되, 하지 않아도 Phase 2의 목적은 달성된다.
- **다른 두 모델(Qwen3·Llama)의 KLUE 확장.** 본 실험의 질문은 EXAONE 붕괴의 도메인
  의존성 하나이며, 대조군은 Kanana 하나로 족하다.

## 9. 파이프라인 변경 범위

프롬프트, 타깃 형식, 판정 코드(`evaluate_followup.py`의 판정 로직), 학습 코드는 손대지
않는다. 변경은 다음 넷뿐이며 모두 KLUE 결과를 보기 전에 커밋한다.

1. **`src/data_prep/audit_klue.py`** (신규) — 실사. 모델 미실행.
2. **`src/data_prep/prepare_klue.py`** (신규) — D1~D7에 따른 데이터 구축.
3. **`src/analysis/comparator_textspan.py`** (신규) — §2 비교 기준 재산출.
4. **채점기 `is_correct()`에 분기 1개** — gold가 리스트면 max-over-golds(D7).
   `evaluate.py`·`evaluate_followup.py` 양쪽 동일. 금융 gold_answer는 항상 문자열이라
   이 분기는 발동하지 않는다.
5. **Modal 래퍼 3개에 `add_local_file` 2줄씩** — 신규 config 2개를 컨테이너에 전달.
   `data/processed`는 `add_local_dir`로 이미 통째로 올라가므로 KLUE 데이터는 추가
   작업이 필요 없다. Stage E(§7)와 동일한 범위의 변경이다.

**(4)는 "채점 코드는 손대지 않는다"를 깨는 변경이므로 회귀 검증을 함께 커밋한다.**
`src/evaluation/regress_finance.py`가 변경 전후의 `metrics_followup_r05.json`을 전수
비교하며, 실행 결과 **판정 관련 31,387개 항목이 모두 1e-12 이내로 일치**했다(H1~H5
점추정·CI, risk-coverage, 운영점 포함). 재현:

```bash
cp results/metrics_followup_r05.json results/metrics_followup_r05.ref.json   # 변경 전 커밋에서
python src/evaluation/evaluate_followup.py --h4-signal m1_conf               # 변경 후
python src/evaluation/regress_finance.py                                     # 종료코드 0
```

`run_inference.py`는 `gold_answer`를 그대로 통과시키므로 수정이 필요 없다.

**1차 지표는 기존 normalize EM을 유지한다.** KLUE 공식 지표(문자 단위 EM·ROUGE-W)로
갈아타면 §2의 비교 기준이 무효가 되므로, 공식 지표는 2차 보고로만 병기한다.

| **무손실형** (EXAONE도 무손실) | 붕괴는 EXAONE × 금융 도메인의 **상호작용**이다. 모델 단독 특성으로는 설명되지 않는다. | 금융의 무엇이 촉발했는지를 가르는 실험. §2가 답 유형 구성 차이를 이미 배제하므로, 남는 후보는 지문 구조(표·수치 밀도)와 도메인 어휘 |
| **미결** (§3 어느 범주도 아님) | 관문 2(EM 바닥) 통과 여부를 먼저 확인하고, 토큰 배율·false abstention 단독으로 재해석한다. | 관문 2에 걸렸다면 KLUE 난이도를 낮춘 하위집합(question_type 1 only)에서 재측정 |
| **대조군 이상** (Kanana도 붕괴) | KLUE 자체가 모든 모델의 답변 습관을 무너뜨리는 것이므로 도메인 축 분리가 실패했다. | 데이터 구축(D1~D7)과 절단 여부를 먼저 점검. EXAONE 결과는 해석 보류 |

어느 쪽이든 보고한다. 무손실형이 나오면 보고서 4.2절의 "원인 미결" 진술을 "도메인
상호작용"으로 좁혀 수정하고, 5장 한계의 "하나의 도메인에서만 실험했다"는 해소된다.

## 11. 기록

- 본 문서는 EXAONE·Kanana의 KLUE M0 추론을 포함해 **어떤 결과도 확인하기 전에** 작성·커밋한다.
- §2의 비교 기준과 §3의 판별 문턱은 기존 금융 결과만으로 산출·고정했으며, KLUE 데이터는
  모델을 돌리지 않는 구조 실사(§4)에만 사용했다.
- H1~H5 기준은 그대로 적용하므로 새로 정하는 판정 문턱은 §3(붕괴 판별)과 §7 관문 2뿐이다.
